    Guide d'exemples de débogage avec Python¶

    Vous trouverez une vue d'ensemble détaillée des exemples de débogage contenus dans ce dépôt. Il détaille le fonctionnement de chaque exemple, les problématiques illustrées, les commandes nécessaires pour les exécuter et la manière d'interagir avec les outils de débogage.

    Outils de débogage¶

    1. print() : La fonction native fondamentale couramment utilisée pour inspecter rapidement la valeur des variables et le flux d'exécution.
    2. trace (python -m trace) : Module de la bibliothèque standard permettant de tracer l'exécution d'un programme ligne par ligne, de compter le nombre d'exécutions de chaque instruction et de générer des rapports de couverture de code sans modifier le code source.
    3. snoop | icecream : Librairies tierces populaires d'inspection et de journalisation : icecream propose une alternative lisible et colorée à print() qui affiche automatiquement le nom de l'expression et sa valeur (ic(x)), tandis que snoop est un décorateur de fonction ou gestionnaire de contexte traçant l'exécution ligne par ligne avec les modifications de variables.
    4. pdb (Python Debugger) : Le débogueur interactif de code source inclus dans la bibliothèque standard de Python. Il permet de poser des points d'arrêt, d'exécuter le code pas-à-pas (step-by-step), d'inspecter les cadres de la pile d'appels (stack frames) et de modifier des variables dynamiquement en cours d'exécution.
    5. faulthandler : Introduit avec Python 3.3, ce module standard intercepte les signaux d'erreur bas niveau (tels que SIGSEGV, SIGFPE, SIGABRT, SIGBUS ou SIGILL) ainsi que les interblocages de threads. Comme ces plantages brutaux tuent le runtime Python avant même que les blocs try...except ne puissent agir, faulthandler écrit directement la pile d'appels Python sur la sortie d'erreur standard ou dans un fichier.
    6. Débogage IPython / Jupyter (ipdb) : Les environnements interactifs intègrent ipdb (une version enrichie de PDB offrant coloration syntaxique et autocomplétion) via des commandes magiques comme %pdb ou %debug, ainsi que la fonction set_trace().

    Exemples PDB (Débogueur interactif Python)¶

    1. pdb-breakpoint.py — Points d'arrêt (breakpoint)¶

    Fichier : pdb-breakpoint.py

    Description¶

    Introduite avec Python 3.7 (PEP 553), la fonction native breakpoint() suspend l'exécution du programme et bascule directement vers le débogueur configuré (par défaut pdb). Dans cet exemple, l'appel à double(val) rencontre immédiatement breakpoint(), interrompt le flux d'instructions et ouvre l'invite de commande (Pdb).

    1
2
3
4
5
6
    def double(x):
   breakpoint()
   return x * 2

val = 3
print(f"{val} * 2 is {double(val)}")

    Exécution¶

    python pdb-breakpoint.py

    Déroulement¶

    Dès le lancement, Python marque une pause à la ligne 2 (breakpoint()) : 

    > pdb-breakpoint.py(2)double()
-> breakpoint()
(Pdb) ll
  1     def double(x):
  2  ->    breakpoint()
  3        return x * 2

(Pdb) n
> pdb-breakpoint.py(3)double()
-> return x * 2

(Pdb) p x
3

(Pdb) q

    • ll (long list) : Affiche l'intégralité du code source de la fonction active, avec -> indiquant la ligne courante.
    • n (next) : Exécute la ligne courante et s'arrête à la ligne suivante (return x * 2).
    • p x (print) : Affiche la valeur de l'argument x (3).
    • q (quit) : Quitte le débogueur et interrompt le programme.

    Contrôler breakpoint() via PYTHONBREAKPOINT¶

    Contrairement à pdb.set_trace(), breakpoint() respecte la variable d'environnement PYTHONBREAKPOINT à l'exécution, ce qui permet de désactiver les points d'arrêt ou de changer de débogueur sans modifier le code source : 

    # Ignorer tous les appels à breakpoint()
PYTHONBREAKPOINT=0 python pdb-breakpoint.py

# Utiliser un débogueur alternatif (ex. ipdb ou pudb)
PYTHONBREAKPOINT=ipdb.set_trace python pdb-breakpoint.py

    2. pdb-set_trace.py — Méthode classique pdb.set_trace()¶

    Fichier : pdb-set_trace.py

    Description¶

    Illustre l'approche traditionnelle employée dans les versions de Python antérieures à 3.7 : l'import explicite du module pdb et l'appel à pdb.set_trace(). L'exemple met également en évidence la capacité du débogueur à évaluer directement des expressions Python à la volée.

def double(x):
   pdb.set_trace()
   return x * 2

    • x * 2 : Évalue n'importe quelle expression Python valide dans le contexte du cadre local.
    • c (continue) : Reprend l'exécution normale du programme jusqu'à la fin ou jusqu'au point d'arrêt suivant.

    3. pdb-average.py — Débogage en ligne de commande, pas-à-pas¶

    Fichier : pdb-average.py

    Description¶

    Lance un script sous PDB sans modifier son code source grâce à l'option -m pdb. La fonction calcule la moyenne d'une liste de nombres. Lorsqu'elle est invoquée avec une liste vide [], une exception ZeroDivisionError est levée lors du calcul total / len(nums).

    4. pdb-condition.py — Points d'arrêt conditionnels¶

    Fichier : pdb-condition.py

    Description¶

    Présente la mise en place d'un point d'arrêt conditionnel qui n'interrompt le programme que lorsqu'une condition spécifique est satisfaite. Dans cette boucle, la fonction parcourt des entiers et doit lever une ValueError dès qu'un nombre est négatif :

    def process(items):
    for i, x in enumerate(items):
        if x < 0:
            raise ValueError(f"Negative value at index {i}")
        print(i, x)

process([1, 2, 3, -1, 5])

    5. pdb-data.py — Initialisation via ligne de commande (-c) et discordance de types¶

    Fichier : pdb-data.py

    Description¶

    Illustre deux concepts clés : 1. Automatiser l'injection d'instructions de débogage dès le démarrage à l'aide du paramètre -c. 2. Diagnostiquer et corriger en mémoire une exception TypeError provoquée par une tentative d'addition entre une chaîne de caractères et un entier ("12" + 5).

    def load_data():
    return {"count": "12"}  # Bogue : count devrait être un entier

def compute_total():
    data = load_data()
    return data["count"] + 5  # TypeError

def main():
    compute_total()

main()

    6. pdb-postmortem.py — Débogage post-mortem en ligne de commande (-c continue)¶

    Fichier : pdb-postmortem.py

    Description¶

    Exécute un script à vitesse normale sous PDB grâce à -c continue (ou -c c) sans définir de point d'arrêt à l'avance. Lorsqu'une exception non interceptée survient dans une sous-fonction (ZeroDivisionError dans invert(x)), PDB bascule automatiquement en mode post-mortem à l'endroit exact de l'erreur, ce qui permet d'examiner la pile d'appels (w) et de remonter (up) à l'origine de l'appel (process(nums)) pour identifier l'itération fautive.

    1
2
3
4
5
6
7
8
    def invert(x):
    return 1 / x

def process(nums):
    for i, n in enumerate(nums):
        print(invert(n))

process([2, 4, 0, 8])

    Exécution¶

    python -m pdb -c continue pdb-postmortem.py

    Déroulement¶

    0.5
0.25
Traceback (most recent call last):
  File "pdb-postmortem.py", line 8, in <module>
    process([2, 4, 0, 8])
  File "pdb-postmortem.py", line 6, in process
    print(invert(n))
  File "pdb-postmortem.py", line 2, in invert
    return 1 / x
ZeroDivisionError: division by zero
Uncaught exception. Entering post mortem debugging
Running 'cont' or 'step' will restart the program
> pdb-postmortem.py(2)invert()
-> return 1 / x

(Pdb) p x
0

(Pdb) w
  pdb-postmortem.py(8)<module>()
-> process([2, 4, 0, 8])
  pdb-postmortem.py(6)process()
-> print(invert(n))
> pdb-postmortem.py(2)invert()
-> return 1 / x

(Pdb) up
> pdb-postmortem.py(6)process()
-> print(invert(n))

(Pdb) p i, n
(2, 0)

(Pdb) q
    • -c continue : Lance immédiatement l'exécution sans s'arrêter à la ligne 1, et n'ouvre PDB que si une exception non gérée est levée.
    • w (where) : Affiche la pile d'appels complète ayant mené à l'exception (<module>() -> process() -> invert()).
    • up : Remonte d'un niveau dans la pile d'appels, de invert(x) vers process(nums), afin d'inspecter l'indice de boucle i (2) et la valeur courante n (0).

    7. faulthandler-segfault.py — Erreurs de segmentation (SIGSEGV)¶

    10. faulthandler-sigusr.py — Inspection à la demande via signal et attachement de processus¶

    Fichier : faulthandler-sigusr.py

Attacher un débogueur interactif PDB à un processus en cours d'exécution via la commande python -m pdb -p <PID>.

faulthandler.register(signal.SIGUSR1)

    12. pdb-postmortem.ipynb — Débogage post-mortem avec %pdb¶

    Fichier : pdb-postmortem.ipynb

    16. hpc-slurm-sigterm.py — Boucle infinie¶

    Fichier : hpc-slurm-sigterm.py

    Description¶

    Dans un environnement de calcul haute performance (HPC), une tâche qui dépasse son temps limite (#SBATCH --time=...), parce qu'elle tourne indéfiniment ou qu'elle atteint simplement le temps alloué, sera arrêtée. Lorsque la tâche est interrompue par Slurm, un délai de 60 secondes est accordé avec l'envoi d'un signal SIGTERM avant que celle-ci ne reçoive un SIGKILL définitif.     17. hpc-mpi-deadlock.py — Interblocages MPI¶

    Fichier : hpc-mpi-deadlock.py

    Description¶

    Lors de l'utilisation de mpi4py réparti sur plusieurs nœuds de calcul, chaque rang MPI s'exécute dans un processus distinct et peut se bloquer en attendant indéfiniment un message. En associant un signal personnalisé (comme SIGUSR1) à faulthandler dans chaque processus (all_threads=True incluant aussi les éventuels threads internes à ce processus), il est possible d'envoyer un signal à l'ensemble des processus via scancel (ou kill) pour afficher l'état de chaque rang.

    import faulthandler
import signal
from mpi4py import MPI

# Registers SIGUSR1 in each MPI rank (process) to print its traceback
faulthandler.register(signal.SIGUSR1, all_threads=True)

comm = MPI.COMM_WORLD
rank = comm.Get_rank()

if rank == 0:
    print("Rank 0 is waiting for rank 1...")
    # Bug: Rank 0 waits for a message that will never be sent
    data = comm.recv(source=1, tag=11)  # Rank 0 process blocks here
else:
    print(f"Rank {rank} is busy...")
    import time
    while True:
        time.sleep(1)  # Other rank process loops here

    Aide-mémoire¶

    Commandes PDB indispensables¶

    Commande Raccourci Description
    next n Pas principal (step over) : exécute la ligne courante sans entrer dans les sous-fonctions.
    step s Pas détaillé (step into) : entre dans la fonction appelée à la ligne courante.
    continue c Poursuit l'exécution jusqu'au prochain point d'arrêt ou jusqu'à la fin.
    return r Poursuit l'exécution jusqu'au retour de la fonction courante.
    longlist ll Affiche l'intégralité du code source de la fonction active.
    list l Affiche 11 lignes de code autour de la ligne courante.
    print p <expr> Évalue et affiche la valeur d'une variable ou d'une expression.
    pp pp <expr> Affiche joliment (pretty-print) la structure d'une variable complexe.
    display display <expr> Affiche automatiquement la valeur de <expr> à chaque arrêt dès qu'elle change.
    undisplay undisplay <expr> Arrête l'affichage automatique de <expr>.
    args a Affiche la liste des arguments reçus par la fonction courante.
    break b <ligne> Définit un point d'arrêt au numéro de ligne indiqué.
    break (cond) b <ligne>, <cond> Définit un point d'arrêt conditionnel qui ne se déclenche que si <cond> est vraie.
    where w Affiche la pile des appels (stack trace), le cadre le plus récent étant en bas.
    up / down u / d Monte ou descend d'un niveau dans la pile des cadres d'exécution.
    quit q Quitte le débogueur et met fin à l'exécution.

    PYTHONBREAKPOINT

    Définir PYTHONBREAKPOINT=0 dans l'environnement pour désactiver tous les appels à breakpoint() sans modifier le code, ou PYTHONBREAKPOINT=<module>.<fonction> (ex. ipdb.set_trace) pour utiliser un débogueur alternatif.

    Commandes et options Faulthandler¶

    Contexte Méthode / Option Description
    Dans le code faulthandler.enable(file=sys.stderr) Active la capture des signaux fatals (SIGSEGV, SIGFPE, SIGABRT, SIGBUS, SIGILL).
    Dans le code faulthandler.dump_traceback_later(timeout) Écrit la trace de tous les threads après un délai d'attente de timeout secondes.
    Dans le code faulthandler.register(signal) Écrit la trace dès la réception d'un signal système spécifique (ex. SIGUSR1).
    Option à la ligne de commandes python -X faulthandler script.py Active le module faulthandler au démarrage de l'interpréteur sans modifier le script.
    Variable d'environnement export PYTHONFAULTHANDLER=1 Active faulthandler de manière globale pour tous les processus Python de la session.

    Commandes magiques IPython / Jupyter¶

    Commande magique Description
    %pdb on Ouvre automatiquement ipdb dès qu'une exception non interceptée se produit.
    %pdb off Désactive l'ouverture automatique du débogueur post-mortem.
    %debug Ouvre ipdb en mode post-mortem sur la dernière exception non gérée.
